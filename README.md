## 👋 What "full stack" means to me

**A full stack developer is someone who adapts to whatever technology the problem needs, and carries the same engineering into it.**

The stack is not the skill. The skill is knowing *why* money must be stored in integer cents, *why* authorization gets checked twice, and *why* an order has to be an immutable snapshot. Those decisions outlive every framework. The tools around them get learned as the problem demands.

Here is that idea as evidence instead of a claim. Three products, and I deliberately solved the same problems three different ways:

| | 🍽️ **RestoPos** | 📈 **Smart Trader** | 💰 **Growly** |
|:--|:--|:--|:--|
| **Data layer** | `pg` driver, hand-written SQL | Drizzle ORM | Prisma |
| **Auth** | JWT built from scratch | Clerk | NextAuth v5 |
| **Frontend** | React 19 + Vite | Next.js 16 App Router | Next.js 16 App Router |
| **Realtime** | Socket.IO | | |
| **Testing** | Vitest | Vitest + PGlite | Vitest + Playwright |
| **Ship it** | Railway + Vercel | Vercel | Vercel |

**Three data layers. Three authentication systems. One year.** Not because I collect frameworks, but because each problem asked for something different and I went and learned it.

## 🚀 Projects

### 🍽️ [RestoPos](https://github.com/raulben6/restopos)

![Live](https://img.shields.io/badge/%F0%9F%9F%A2_running_in_production-10B981?style=flat-square)
![Node](https://img.shields.io/badge/Node.js-339933?style=flat-square&logo=nodedotjs&logoColor=white)
![Socket.IO](https://img.shields.io/badge/Socket.IO-010101?style=flat-square&logo=socketdotio&logoColor=white)
![PostgreSQL](https://img.shields.io/badge/PostgreSQL-4169E1?style=flat-square&logo=postgresql&logoColor=white)
![React](https://img.shields.io/badge/React_19-61DAFB?style=flat-square&logo=react&logoColor=black)

**A real-time POS deployed at a working restaurant.** A waiter takes an order on a tablet, the kitchen screen updates instantly, the ticket prints on a thermal printer, and the owner watches revenue on a dashboard.

The hard part was never the CRUD. It was **dual-channel pricing** (dine-in vs. delivery commission), **immutable order snapshots** so editing tomorrow's menu never rewrites yesterday's receipts, and **ESC/POS thermal printing** pushed over raw TCP.

### 📈 [Smart Trader Performance System](https://github.com/raulben6/smart-money-app)

![Tests](https://img.shields.io/badge/302_tests-6E9F18?style=flat-square&logo=vitest&logoColor=white)
![Next.js](https://img.shields.io/badge/Next.js_16-000000?style=flat-square&logo=nextdotjs&logoColor=white)
![Drizzle](https://img.shields.io/badge/Drizzle-C5F74F?style=flat-square&logo=drizzle&logoColor=black)
![Clerk](https://img.shields.io/badge/Clerk-6C47FF?style=flat-square&logo=clerk&logoColor=white)
![Neon](https://img.shields.io/badge/Neon-00E599?style=flat-square&logo=neon&logoColor=black)

**A trading journal with a mentor on the other side of it.** A mentor invites students, reviews their trades and journals, assigns objectives, and moves them through levels as performance improves.

Two decisions define it. **Metrics are always derived from trades, never stored**, so a cached total can never drift from reality. And **authorization is enforced twice**, once at the Server Action and again inside every query, so a new call site cannot bypass it by accident. That second layer is proven by an authorization matrix running against a real Postgres embedded in the test process.

### 💰 [Growly](https://github.com/raulben6/growly)

![Tests](https://img.shields.io/badge/283_tests_+_E2E-6E9F18?style=flat-square&logo=vitest&logoColor=white)
![Next.js](https://img.shields.io/badge/Next.js_16-000000?style=flat-square&logo=nextdotjs&logoColor=white)
![Prisma](https://img.shields.io/badge/Prisma_6-2D3748?style=flat-square&logo=prisma&logoColor=white)
![NextAuth](https://img.shields.io/badge/NextAuth_v5-000000?style=flat-square&logo=nextdotjs&logoColor=white)
![Playwright](https://img.shields.io/badge/Playwright-2EAD33?style=flat-square&logo=playwright&logoColor=white)

**Personal finance built as a real product.** Accounts, transfers, envelope budgets, savings goals, recurring rules, a payment calendar and alerts.

Money lives in **integer cents, never floats**, because `0.1 + 0.2 !== 0.3` compounds across every rollup in a budgeting app. Recurring transactions are **idempotent by a database constraint** instead of trusting a job to run exactly once.
